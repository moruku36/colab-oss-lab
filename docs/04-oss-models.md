# OSSモデルを載せると、何ができるのか

## OSSモデルとは

OSSは「オープンソース」の略です。  
ここでは広く、**重み（学習済みの中身）が公開されていて、自分の機械で動かせるモデル** を指します。

代表的な置き場は [Hugging Face](https://huggingface.co) です。  
アプリの店ではなく、モデルの倉庫に近い場所です。

Gemini や ChatGPT の本体は、基本的に自分の機械には降りてきません。  
OSSモデルは降ってきます。その代わり、机の広さ（VRAM）と手数は自分持ちです。

## 載せられるものの目安（L4 / 約22.5GB）

数字は「パラメータ数」です。モデルの大きさの目安で、賢いさの保証ではありません。

量子化（圧縮）しない場合、8Bでも机がいっぱいになりがちです。  
**4bitに圧縮する**のが今の標準です。

| 大きさの目安 | L4での推論 | L4での追加学習 |
|---|---|---|
| 3B〜8B | 余裕 | しやすい |
| 8B〜14B | 4bitなら現実的 | 本線 |
| 20B前後 | 4bitなら狙える | 設定を詰める必要あり |
| 27B〜31B | 4bitなら載る（[実験02](results/02_quantization_max.md) で 31B が 17GB） | 基本は無理 |
| 32B〜36B | 4bitで載るが、文章は 2K〜4K トークンまで（[実験07](results/07_l4_limit.md)） | 無理 |
| 70B級 | この机には載らない | 載らない |

「一番いいGPUを選べば、一番いいモデルが使える」ではありません。  
載るサイズの中から、新しい良いモデルを選ぶ方が重要です。

2026年時点でよく試される名前の例:

- Qwen 系
- Gemma 系
- gpt-oss 系
- Llama 系のうち、サイズが載るもの

名前が新しくても、大きすぎればL4では動きません。

## 載せたあと、何ができるか

1. **会話する**  
   質問を投げて、返事を見る。モデルごとの癖を知る。

2. **日本語の様子を見る**  
   同じ質問をGeminiと比べる。崩れる点、得意な点をメモする。

3. **追加学習する**  
   自分の例文を少し与えて、薄い部品（LoRA）を作る。

4. **変換して持ち帰る**  
   家のPC用のファイルにする。

5. **失敗を記録する**  
   メモリ不足、切れ、遅い、日本語が変、を残す。検証の本体はここです。

## まだ載せない方がいいもの

- 社外秘の文章そのもの
- 個人情報たっぷりのログ
- 「動かしっぱなし」が前提のボット

Colabの機械は共有の借り物です。消える前提で使います。

## 最初の成功条件

次ができれば、第一歩は十分です。

1. L4 が当たっている
2. 小さなOSSモデルが1個動く
3. 短い日本語の質問に返事が返る
4. ノートを閉じても、手順がこのリポジトリに残っている

速さや、最大モデルは後回しで構いません。
