# 02. 量子化で L4 に載る最大モデル

## 結論（先に）

- **想定どおり動いた。** 4つの判定がすべて合格（下の実行記録）。
- **L4（VRAM 22GB）に 4bit 量子化で載る最大クラスは、約 30B（300億パラメータ）前後の密モデル。**
- 今回選んだのは [`google/gemma-4-31B-it`](https://huggingface.co/google/gemma-4-31B-it)（31.3B、Apache-2.0、ゲートなし）。
- ノート: [notebooks/02_quantize_largest_model_on_l4.ipynb](../../notebooks/02_quantize_largest_model_on_l4.ipynb)

## どうやって「最大」を決めたか

目安の式: **必要な VRAM ≒ パラメータ数 × 1個あたりのバイト数 + 余白（1〜3GB）**

| 形式 | 1パラメータ | 22GB に載る上限の目安 |
| --- | --- | --- |
| bf16（量子化なし） | 2 バイト | 約 9B |
| 8bit | 1 バイト | 約 18B |
| **4bit（NF4 / AWQ / GPTQ）** | **約 0.5 バイト** | **約 32〜35B** |
| 2〜3bit | 約 0.3 バイト | 約 60〜70B（品質が大きく落ちる） |

余白に入るもの: CUDA の作業領域、会話の記憶（KV キャッシュ）、量子化しない部分（埋め込み層など）。

### gemma-4-31B-it を 4bit にしたときの見積もり

- 埋め込み層 262,144 語 × 5,376 = 約 1.4B パラメータ → bf16 のまま約 2.8GB（入力と出力で共有）
- 残り約 29.9B → 4bit（NF4 + double quant）で約 15.4GB
- 合計 **約 18〜19GB** → 22GB に収まり、2〜3GB の余白が残る

### 候補にして外したもの（2026-09 時点で Hugging Face を確認）

| モデル | 理由 |
| --- | --- |
| `google/gemma-4-31B-it-qat-w4a16-ct`（公式 4bit 版） | ファイルだけで 23.3GB。22GB に載らない |
| `Qwen/Qwen3.8-27B` | 4bit で載るが 27.8B で Gemma 4 31B より小さい |
| `Qwen/Qwen-AgentWorld-35B-A3B` など MoE 35B | 数字上は 4bit で約 19GB だが、MoE の専門家層は bitsandbytes でうまく縮まない場合があり不確実 |
| `meta-llama/Llama-3.3-70B-Instruct` | 2bit まで落とせば数字上は載るが、品質低下が大きく、利用規約への同意（ゲート）も必要 |
| `Qwen/Qwen3.8-Flash-Next`（180B MoE）など | 4bit でも 90GB 以上。無理 |

**「想定どおり動いた」の基準**（ノートが自動判定する）

1. モデル全体が GPU に載る（CPU に逃がさない）
2. 読み込み後の VRAM 使用量が 20GB 以下
3. 日本語の返事が返る
4. 生成が最後まで終わる

### 質問: 小学校の児童にも分かる言葉で、GPUとVRAMの違いを3文で説明してください。

速度: 74 トークン / 13.8 秒 = 5.4 トークン/秒

```
GPUは、計算をめちゃくちゃ速くこなす「頭脳（計算機）」のことです。
VRAMは、計算に使うデータを一時的に置いておく「机（作業スペース）」のことです。
頭脳（GPU）がどれだけ速くても、机（VRAM）が狭いと一度にたくさんの作業ができなくなります。
```

### 質問: りんごが3個入った箱が4つあります。そこから5個食べて、2個もらいました。りんごは何個ですか。考え方も短く書いてください。

速度: 37 トークン / 6.4 秒 = 5.8 トークン/秒

```
答え：**11個**

【考え方】
(3個 × 4箱) － 5個 ＋ 2個 ＝ 11個
```

## ふりかえり

### 見積もりと実測

| 項目 | 見積もり | 実測 |
| --- | --- | --- |
| VRAM（読み込み後） | 18〜19 GB | **17.0 GB** |
| 余白 | 2〜3 GB | **約 5 GB** |

見積もりより 1.5〜2GB 小さかった。画像用の部品（vision tower）などが想定より小さかったと考えられる。
余白が 5GB あるので、4bit なら **35B 前後の密モデルまでは入る可能性がある**。ただし長い文章を入れると KV キャッシュが増えるので、31B は「普段使いで安全に載る上限」と考えるのがよい。

### 01（1.5B）との比較

| | 01: Qwen2.5-1.5B（量子化なし） | 02: Gemma 4 31B（4bit） |
| --- | --- | --- |
| パラメータ | 1.5B | 31.3B（約20倍） |
| GPU/VRAM の説明 | 「VRAM＝視覚記憶エリア」など不正確 | 「頭脳と机」のたとえで正確 |
| 計算問題 | 未実施 | 正解（11個） |
| 速さ | 速い | 約 5.5 トークン/秒（ゆっくり読める程度） |

量子化で 62GB → 16.6GB（約 1/4）になり、20倍大きいモデルを同じ L4 で動かせた。日本語の質ははっきり上がった。

### 気づいたこと・次の候補

- 速度は約 5.5 トークン/秒。bitsandbytes は「載せる」のは得意だが速くはない。速さが必要なら vLLM + AWQ/GPTQ 形式を試す
- 毎回 62GB をダウンロードして変換するので、読み込みに約 6 分かかる。量子化済みの重みを Google Drive や Hugging Face に保存すれば短くできる
- `HF_TOKEN` 未設定の警告が出た（ゲートのないモデルなので動作には影響なし）。Colab の「シークレット」に入れるとダウンロード制限が緩くなる
